# Cortexa developer documentation

## Project

This repository contains public, English-language documentation for the Cortexa
Scribe partner API. Pages are MDX; Mintlify configuration is in `docs.json`.

Run `npx --yes mint@4.3.23 instructions` before Mintlify work and read the topic
relevant to the change. Use the existing backend contract and guides for product
facts. Do not invent endpoints, credentials, domains, availability, or limits.

## Terminology and writing

- Use **workspace** for the clinician's Cortexa workspace.
- A **partner application** holds server-side credentials; a **grant** binds it
  to a clinician and workspace.
- A **session** is a consultation; a **document** is a generated or edited output.
- Use concise active sentences, second person, and sentence-case headings.
- Put a title and description in frontmatter; begin body sections at `##`.
- Use root-relative page links and synthetic data in examples.
- Describe current Cortexa behavior without competitor comparisons or development
  history. Explain prerequisites that affect an integrator's next action.

## Contract and content boundaries

- `openapi.json` and `postman.json` are generated by the server's partner exporter.
  Follow README.md to refresh them; change API behavior in the server repository.
- Keep all exported operations in the API reference navigation when updating it.
- Keep private deployment runbooks, admin APIs, patient data, and real credentials
  out of this public repository.
- Mintlify connection, domain setup, and production rollout are managed by the
  project owner.

## Validation and Git

Run `npx --yes mint@4.3.23 validate` and
`npx --yes mint@4.3.23 broken-links` after content or navigation changes. Preview
changed pages with `npx --yes mint@4.3.23 dev`.

Use `codex/` feature branches and pull requests to `main`. Do not push directly to
`main` or `dev`.
