The current public contract contains **48 operations** under
`/v2/scribe/open-api`. The API reference tab lists each operation's request and
response schemas. These guides explain how to combine them into a clinical workflow.

## Supported workflows

| Area | Available operations | Guide |
| --- | --- | --- |
| Authentication | Exchange a clinician authorization code or valid grant for a JWT; retrieve public keys | [Authentication](/authentication) |
| Patients | Create, list, retrieve, update, delete, batch delete, and link/unlink sessions | [Patients](/patients) |
| Sessions | Create, list, retrieve, update, and delete consultations | [Sessions](/sessions) |
| Clinical context | Session background text; upload, list, and detach context documents | [Context](/context) |
| Transcript text | Append ordered batches and retrieve the combined transcript | [Transcripts](/transcripts) |
| Complete audio | Create an upload, obtain signed part URLs, complete, and process the recording | [Recordings](/recordings) |
| Audio during a consultation | Start a recording, transcribe indexed chunks, and finish the assembled transcript | [Segmented transcription](/segmented-transcription) |
| Templates | List all or category-specific templates; retrieve detail | [Templates](/templates) |
| Consult notes | Queue generation and edit the latest completed note | [Notes](/notes) |
| Documents | Create, list, retrieve, edit, delete, and generate/regenerate content | [Documents](/documents) |
| Custom prompts | Create a private prompt-based template and generate a document | [Custom templates](/custom-templates) |
| Ask AI | Submit a session question and retrieve the answer | [Ask AI](/ask-ai) |
| Coding | Start/retrieve code suggestions; request US outpatient MDM-based E/M assessment | [Clinical coding](/clinical-coding) |
| Jobs | Retrieve processing status and failure codes | [Jobs](/jobs) |
| Workspace directory | Read the authorized workspace and its active members | [Directory](/workspace-directory) |

## Integration model

The API is designed for backend integration. Your application handles clinician
consent coordination, audio capture, the review UI, and saving results in your EHR.
A grant binds your application to one clinician and workspace, and isolates its
patients and sessions. See [the complete flow](/integration-flow).

| Integration need | Current approach |
| --- | --- |
| Sign in and authorize | Cortexa clinician login plus the consent flow agreed during onboarding |
| Call clinical endpoints | Partner JWT from the API-key/token exchange |
| Know when processing finishes | Poll job or workflow-result endpoints |
| Update clinical text | Versioned document edits using `base_version` |
| Map output into EHR fields | Your integration maps returned content to your own fields |
| Retrieve patient history | Submit the relevant authorized context explicitly |
| Configure regional hosting and supported languages | Confirm with Cortexa for your environment |

## Public API boundaries

The current contract does not expose an embedded widget/client SDK, a general
third-party REST/MCP connector registration program, completion webhooks, a
partner usage-analytics API, or vendor-specific FHIR/HL7 adapters.

It also does not expose a combined patient-and-session setup call, a sectional-note
conversion API with stored EHR-field mappings, a previous-session context-linking
endpoint, or PDF/DOCX document downloads. Internal product functionality does not
automatically make these operations available to partner JWTs.

Custom template generation accepts a name and prompt; it does not accept an
arbitrary output JSON schema. Audio during a consultation uses HTTP chunks rather
than a public WebSocket connection. Note generation returns jobs and documents
rather than streaming generated text in the generation response.

## Availability and permissions

An implemented operation still depends on application scopes, clinician workspace
permissions, plan entitlements, quotas, and the configured provider. Coding systems
and language support must be confirmed for the integration's environment.

The sandbox hostname exposes the public contract; it is not a clinician login
site. Agree production access and acceptance with your integration contact using
[Sandbox](/sandbox) and [production preparation](/production).
