title: "Use the JavaScript SDK"
description: "Create consultations, upload audio, and consume generated text in a browser or JavaScript application."
---

The SDK is an ES module served by your Cortexa API environment. It uses standard
`fetch`, `ReadableStream`, and `FormData`, and includes TypeScript declarations.
No npm publication or build step is required for the hosted browser module.

## Load and authorize the client

```javascript
const baseUrl = 'https://sandbox.api.cortexanote.com/v2/scribe/open-api';
const { CortexaClient } = await import(`${baseUrl}/assets/sdk.mjs`);

const client = new CortexaClient({
  baseUrl,
  getToken: async ({ refresh }) => {
    // Your backend exchanges its API key and the clinician's saved grant.
    const response = await fetch('/api/cortexa/clinician-token', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ refresh })
    });
    if (!response.ok) throw new Error('Clinician authorization is unavailable');
    return (await response.json()).access_token;
  }
});
```

`/api/cortexa/clinician-token` is an example route **you implement** on your backend.
Never embed the application API key in a browser bundle. You can instead pass
`token` and later call `client.setToken(...)`. When `getToken` is provided, the SDK
calls it for each request; your implementation can cache the short-lived JWT. On
`401` it calls it once with `refresh: true` and retries once.

For direct browser API calls, arrange your origin in the environment's CORS
allowlist. The hosted [Widget](/widget) calls the API from its iframe's own origin.
In Node.js, download the module and adjacent `sdk.d.ts` from your assigned
environment, then import the local module using a runtime with these web APIs.

## Create and generate

```javascript
const opened = await client.workflow({
  patient: { external_patient_id: 'synthetic-patient-001', name: 'Synthetic Patient' },
  session: { external_session_id: 'synthetic-visit-001' }
}, 'synthetic-visit-001-open');

const sessionId = opened.session.id;
await client.appendTranscript(sessionId,
  'Synthetic consultation. Patient reports improved sleep. Review in two weeks.',
  'synthetic-visit-001-transcript');

for await (const event of client.generateNote(sessionId, {}, {
  key: 'synthetic-visit-001-note'
})) {
  if (event.event === 'output.generating' && event.data.reset) clearDraft();
  if (event.event === 'output.delta') appendDraft(event.data.data);
  if (event.event === 'output.ready') showSavedDocument(event.data.document);
  if (event.event === 'output.failed' || event.event === 'generation.failed') {
    showFailure(event.data.failure_code);
  }
}
```

`clearDraft`, `appendDraft`, `showSavedDocument`, and `showFailure` are your UI
functions. Render returned text as text or sanitized Markdown, not raw HTML.
The saved document's `current_version` is required when saving clinician edits.

## Reconnect a generation

Persist the request body, idempotency key, and last received `event.id`. Call the
same generation method with those values and `lastEventId` after a disconnect.
Keep one cursor per generation request. `AbortSignal` stops your local stream;
it does not cancel the durable server job.

The SDK yields the [public SSE events](/streaming), including failure events. It
does not silently start a new generation when the stream ends. Treat a stream
without `output.ready` for every expected document as incomplete. Network errors
are not automatically retried; keep your operation key when retrying a lost response.

## Common methods

| Method | Use |
| --- | --- |
| `workflow(body, key)` | Create or resume the patient and consultation |
| `linkContext(sessionId, sourceIds)` | Replace historical note links |
| `startRecording(sessionId, key)` | Open a segmented audio recording |
| `transcribeSegment(sessionId, recordingId, blob, index, duration)` | Upload a complete audio segment; duration is seconds |
| `finishRecording(sessionId, recordingId)` | Assemble the ordered transcript |
| `generateNote(...)`, `generateDocument(...)` | Receive generated text and saved results |
| `getDocument(...)`, `updateDocument(...)` | Read and save versioned clinician edits |
| `sections(sessionId)` | Convert the latest note to mapped sections |
| `structuredResponse(sessionId, form, key)` | Generate typed form answers |
| `usage(query)` | Query the current grant's daily activity |
| `connectorTools()`, `callConnector(...)` | Discover connected tools and propose calls |
| `request(path, options)` | Call any other documented API-relative route |

`CortexaError` exposes `status` and the parsed error `body`. Preserve request IDs
from your network tooling for support. Type declarations are available at
`/v2/scribe/open-api/assets/sdk.d.ts`.
