After testing in the sandbox, contact Cortexa to set up your production integration.

## Set up production access

| Item | Confirm with Cortexa |
| --- | --- |
| Environment | API address, Cortexa app URL, and hosting arrangements |
| Application | Production application ID, API key, and registered HTTPS callback |
| Access | Workspaces, scopes, templates, and entitlements |
| Workflows | Languages, audio formats, attachment processing, and coding systems |
| Limits | Application request allowance and generation quotas |

Use the credentials and addresses issued for production. Sandbox grants and
resource IDs are specific to the sandbox environment.

## Check the clinician journey

1. Connect a clinician, verify callback `state`, and renew a token with the saved grant.
2. Run the audio, templates, languages, and attachments your product offers.
3. Process generation events and job status, handle failures, and reconnect interrupted streams.
4. Save clinician edits and handle document version conflicts.
5. Write the reviewed result to the correct patient and encounter in your EHR.

[Connectors](/connectors) support approved external writes.

## Deliver streamed responses

If your backend proxies generation, forward SSE frames as they arrive. Disable
buffering and caching, preserve event IDs, and allow enough connection time for
generation. Check incremental delivery and reconnection through your deployed proxy.

For JSON receipts and polling, set `stream=false`. See [Streaming](/streaming).

## Operate the integration

Keep the API key on your backend. Renew JWTs using `expires_in`; reconnect the
clinician if their grant is no longer valid. Honor `Retry-After` on rate limits
and increase polling intervals for longer [jobs](/jobs).

For support, record the HTTP status, failure code, and `X-Cortexa-Request-Id`.
Keep clinical payloads and credentials out of ordinary logs. See [Errors](/errors)
for recovery steps.
