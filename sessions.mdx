---
title: "Create and manage sessions"
description: "Represent one consultation and keep its transcript, context, and documents together."
---

A **session** is one consultation. It holds the transcript and context used to
generate notes, and the documents created from that consultation.

Use the same Partner JWT grant for the patient, session, and subsequent requests.
Read operations require `scribe:read`; create, update, and delete require
`scribe:write`.

## Create a session

`POST /sessions`

```bash
curl --request POST "$CORTEXA_API_BASE/sessions" \
  --header "Authorization: Bearer $CORTEXA_JWT" \
  --header 'Content-Type: application/json' \
  --data "{\"external_session_id\":\"ehr-visit-001\",\"patient_id\":\"$CORTEXA_PATIENT_ID\",\"title\":\"Synthetic follow-up\",\"background_context\":\"Synthetic patient attending a follow-up.\",\"input_languages\":[\"en\"],\"output_language_code\":\"en\"}"
```

| Field | Required | Meaning |
| --- | --- | --- |
| `external_session_id` | Yes | Stable encounter ID from your EHR; 1–255 characters |
| `patient_id` | No | Cortexa patient ID from this grant |
| `title` | No | Session label; up to 255 characters |
| `background_context` | No | Relevant clinical background; up to 100,000 characters |
| `input_languages` | No | Up to three input language codes |
| `output_language_code` | No | Language requested for generated output |
| `template_ids` | No | Up to 20 available template IDs to associate with the session |

Example `201` response:

```json
{
  "id": "session_example",
  "external_session_id": "ehr-visit-001",
  "patient_id": "patient_example",
  "title": "Synthetic follow-up",
  "status": "idle",
  "background_context": "Synthetic patient attending a follow-up.",
  "input_languages": ["en"],
  "output_language_code": "en",
  "created_at": "2026-11-16T10:00:00Z"
}
```

Save the returned `id` as `CORTEXA_SESSION_ID`. Repeating a create request with the
same external session ID returns the existing session within the grant. It does
not update its fields. A deleted session's external ID remains reserved.

## Reopen a consultation

Keep the mapping between your encounter ID and the returned Cortexa session ID.
On reopening the encounter, use `GET /sessions/{session_id}` and list its
[documents](/documents). If you only have your own ID, look it up with:

```bash
curl --get "$CORTEXA_API_BASE/sessions" \
  --header "Authorization: Bearer $CORTEXA_JWT" \
  --data-urlencode 'external_session_id=ehr-visit-001'
```

The response uses the standard [paginated list](/errors#pagination).
Create the patient and session in separate requests; the API does not expose a
combined patient-and-session setup endpoint.

## Update session details

`PATCH /sessions/{session_id}` accepts `title`, `background_context`, and
`output_language_code`.

```bash
curl --request PATCH "$CORTEXA_API_BASE/sessions/$CORTEXA_SESSION_ID" \
  --header "Authorization: Bearer $CORTEXA_JWT" \
  --header 'Content-Type: application/json' \
  --data '{"background_context":"Updated synthetic history for the next generation."}'
```

Changing context does not rewrite a previously generated document. Request new
content when the clinician wants the updated information reflected in the output.
Use [patient-session links](/patients#attach-existing-sessions) to change the
patient association; `patient_id` is not accepted by this PATCH endpoint.

## Delete a session

`DELETE /sessions/{session_id}` returns:

```json
{"deleted": true}
```

The session is no longer accessible through the partner API. Deleting a patient
and deleting a session are separate operations.
