## Start in the sandbox

The sandbox base URL is:

```text
https://sandbox.api.cortexanote.com/v2/scribe/open-api
```

Arrange sandbox access with your Cortexa integration contact. You need an
application ID, a server-side API key, a registered HTTPS callback, and a clinician
authorization for a Cortexa workspace. Use synthetic encounters while developing
your integration. Confirm the consent entry point and production access with
Cortexa during onboarding.

## Integration workflow

1. Obtain the clinician's authorization for a specific workspace.
2. Exchange the one-time authorization code for a short-lived JWT.
3. Create a patient and session using your EHR's external IDs.
4. Submit a transcript or recording and request a clinical note.
5. Poll the job and retrieve the completed document.
6. Present the draft for clinical review and save it through your EHR's own API.

## Resource ownership

Each authorization, called a **grant**, binds your application, an external
clinician ID, a Cortexa user, and a workspace. Your application can hold grants for
clinicians in multiple workspaces. Patients and sessions created through a grant
are accessible only through that grant. Existing internal Cortexa sessions are not
automatically shared with partners.

Switching the clinician's active workspace in Cortexa does not change a grant.
Keep the returned `grant_id` with your EHR's clinician and workspace mapping.

`external_patient_id` and `external_session_id` are unique within a grant.
Repeating a create request with the same external ID returns the existing resource;
use PATCH to update its contents. A deleted resource's external ID remains reserved.

## Available workflows

The API covers patients, sessions, templates, versioned documents, Ask AI, clinical
coding, E/M suggestions, context attachments, recordings, and the authorized
workspace directory. See [API capabilities](/capabilities) for the supported scope
and [Extended workflows](/workflows) for request examples.

Cortexa's clinical permissions, plan entitlements, and generation quotas apply.
Your EHR provides recording controls and saves reviewed results. Webhooks,
embedded widgets, and vendor-specific FHIR/HL7 adapters are outside the current
API scope.
