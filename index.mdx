Add clinical documentation to your EHR, telehealth platform, or clinical application.
Send a consultation's transcript or audio, provide relevant patient context, and
retrieve a draft note for the clinician to review and save.

Choose a backend API integration, the JavaScript SDK, or the embedded Widget.
Your application supplies the patient and encounter identity; Cortexa can provide
recording, streamed generation, and a review interface. Write the reviewed result
through your EHR API or a clinician-approved connector.

## A consultation in six steps

1. Obtain the clinician's authorization and exchange it for a Partner JWT.
2. Create a patient and session using your EHR's external IDs.
3. Add relevant context and submit transcript text or audio.
4. Select a template and request a note.
5. Display streamed text and receive the completed document in the same response.
6. Let the clinician review it, then save the result through your EHR's API.

See [How an integration works](/integration-flow) for the complete sequence and
[Quickstart](/quickstart) for executable requests.

## Know the core objects

| Object | Meaning |
| --- | --- |
| Partner application | Your integration and its server-side credentials |
| Grant | Permission for your application to act for one clinician in one workspace |
| Patient | Patient record accessible through that grant |
| Session | One consultation, including its clinical inputs and outputs |
| Template | Instructions and structure for an output |
| Document | A generated or edited note, letter, or other output |
| Job | Background work whose status you can poll |

A grant is the access boundary. Patients and sessions created under one grant
are not automatically visible under another, and internal Cortexa sessions are
not automatically shared with partners. Save resource IDs alongside the grant
that created them.

## Start in the sandbox

```text
https://sandbox.api.cortexanote.com/v2/scribe/open-api
```

Arrange access with your Cortexa integration contact. A clinician test account,
an application API key, and a Partner JWT serve different purposes; the
[Sandbox guide](/sandbox) explains what you need before the first request.

Clinical permissions, plan entitlements, and generation quotas apply. Review
[API capabilities](/capabilities), [FAQ](/faq), and
[production preparation](/production) as you plan your integration.
