Combine the API calls into common clinical workflows. Use the same grant for
each consultation and wait for required inputs to finish processing.

## Record a consultation and produce a note

1. [Open the patient and session](/session-workflow) using your EHR's IDs.
2. [Add background text or reports](/context). Wait for required files to be ready.
3. Upload audio chunks through [segmented transcription](/segmented-transcription),
   process each returned transcript, then finish the recording.
4. [Generate a consult note](/notes) with the clinician's selected template.
5. [Consume the stream](/streaming) and use the saved `output.ready` document for clinician review.
6. Save reviewed edits and write the result to your EHR's encounter.

If the full recording already exists, replace step 3 with the
[complete recording upload](/recordings) workflow.

## Produce a referral from the same consultation

1. Reopen the existing session instead of creating another encounter.
2. Select a [document template](/templates).
3. [Create a document](/documents#create-an-empty-document) titled for the referral.
4. Request [content generation](/documents#generate-or-regenerate-content) and wait for `output.ready`.
5. Let the clinician review and edit the document, then save it through your EHR.

For a new prompt-based output, such as patient instructions, use
[Custom template responses](/custom-templates). That endpoint creates a private
template and queues its document in one request.

## Reopen and edit a completed note

1. Look up the saved Cortexa session ID for the current grant and encounter.
2. List its documents and retrieve the selected document.
3. Retain `current_version` while the clinician edits the text.
4. PATCH the document with that value as `base_version` and the edited content.
5. If you receive `409`, retrieve the newer document and resolve the conflict.
6. Save the accepted text through your EHR API and retain the new Cortexa version.

## Add coding to a completed encounter

1. Complete the consult-note workflow and have the clinician review the note.
2. Request [clinical code suggestions](/clinical-coding) for enabled code systems.
3. For supported US office/outpatient visits, request an E/M assessment with the
   correct new/established patient type.
4. Present supporting evidence and any insufficient-documentation result.
5. Let the clinician choose what to use in your billing workflow.

Editing the note changes its version and invalidates cached E/M assessment.
Obtain the assessment for the reviewed version before displaying it as current.
