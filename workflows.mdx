These recipes connect the individual endpoint guides. Every step uses the same
grant, and every asynchronous result must be ready before its dependent step.

## Record a consultation and produce a note

1. [Create or find the patient](/patients) using your stable EHR patient ID.
2. [Create the session](/sessions) using your encounter ID and the returned patient ID.
3. [Add background text or reports](/context). Wait for required files to be ready.
4. Capture audio in your application and use [segmented transcription](/segmented-transcription).
   Display per-chunk text as it returns, then finish the recording.
5. [Generate a consult note](/notes) with a clinician-selected template.
6. [Display the stream](/streaming) and use `output.ready` to present the saved draft for review.
7. Save reviewed edits and write the result to your EHR's encounter.

If the full recording already exists, replace step 4 with the
[complete recording upload](/recordings) workflow.

## Produce a referral from the same consultation

1. Reopen the existing session instead of creating another encounter.
2. Select a [document template](/templates).
3. [Create a document](/documents#create-an-empty-document) titled for the referral.
4. Request [content generation](/documents#generate-or-regenerate-content), display its text, and wait for `output.ready`.
5. Let the clinician review and edit the document, then save it through your EHR.

For a new prompt-based output, such as patient instructions, use
[Custom template responses](/custom-templates). That endpoint creates a private
template and queues its document in one request.

## Reopen and edit a completed note

1. Look up the saved Cortexa session ID for the current grant and encounter.
2. List its documents and retrieve the selected document.
3. Retain `current_version` while the clinician edits the text.
4. PATCH the document with that value as `base_version` and the edited content.
5. If you receive `409`, retrieve the newer document and resolve the conflict.
6. Save the accepted text through your EHR API and retain the new Cortexa version.

An internal Cortexa session not shared through your grant is not accessible through
this flow. Use the partner-created resource mapping, not an arbitrary product URL.

## Add coding to a completed encounter

1. Complete the consult-note workflow and have the clinician review the note.
2. Request [clinical code suggestions](/clinical-coding) for enabled code systems.
3. For supported US office/outpatient visits, request an E/M assessment with the
   correct new/established patient type.
4. Present supporting evidence and any insufficient-documentation result.
5. Let the clinician choose what to use in your billing workflow.

Editing the note changes its version and invalidates cached E/M assessment.
Obtain the assessment for the reviewed version before displaying it as current.

## Build a useful progress UI

| Stage | What your interface can show |
| --- | --- |
| Sending audio or context | Upload progress and retry controls owned by your client |
| Waiting for transcription | Transcription job status, or accepted segment text |
| Generating output | Incoming text per document; reconnect if the stream drops |
| Ready | Reviewable document text and its current version |
| Failed | A recoverable action based on the failure code, rather than a perpetual spinner |
| Saving | Confirmation from your own EHR write-back |

Use [Streaming](/streaming), [Jobs](/jobs), and [Errors and retries](/errors) to implement these states.
